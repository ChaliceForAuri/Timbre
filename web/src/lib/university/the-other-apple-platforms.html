Modules 1 to 11 are the Mac. The companion (GDR-0023, GDR-0026) is an iPhone and an Apple Watch, and almost everything you have learned transfers untouched: the language, the concurrency model, SwiftUI, the on-device models. What does not transfer is precisely what Timbre's Mac app is made of — reaching into other apps.

One language, three sandboxes

On the Mac, Timbre runs without the App Sandbox (ADR-0003) so that it can send a synthetic ⌘V, read the focused field through the Accessibility API, and watch a modifier key from anywhere. iOS and watchOS have no such mode. Every app is sandboxed; there is no Accessibility API into other apps, no synthetic events, no global hotkey, no menu bar, and no way to put text into a field you do not own. GDR-0002 drew the conclusion in 2026-08 and it still holds: dictation into other apps is a Mac feature.

What the other platforms offer instead is a fixed set of places to appear, each with its own framework: the Home and Lock Screens, Control Center, Siri and Spotlight, the share sheet, the Dynamic Island, the watch face, the Smart Stack. A companion is designed by choosing which of those places each feature belongs in.

What iOS gives you

  • App Intents. One declaration makes a feature available to Siri, Shortcuts, Spotlight, the Action Button and Control Center. "Add ephemeral to my Library" and "what does ADR mean" are intents, not screens.
  • WidgetKit. Home Screen and Lock Screen widgets, and since iOS 18 Controls: a button in Control Center or on the Lock Screen that runs an intent without opening the app. The to-do key's phone-side home.
  • ActivityKit. Live Activities: a card on the Lock Screen and in the Dynamic Island for something in progress. The pill, translated.
  • Share extensions. Text selected in any app can be sent to Timbre; nothing can be sent back into the field it came from. Read-aloud fits that shape (GDR-0008); fix does not.
  • Background time is short and scheduled, never a daemon. Anything that must happen while the app is closed is a notification or a widget refresh, not a loop.

Trap · a framework in the SDK is not an API you can call

Two ways to be fooled, and Timbre was fooled by both before the first build. EventKit is in the watchOS SDK, so a record said the Watch could file a reminder; the header marks every write __WATCHOS_PROHIBITED, and only reading survives. Check the header, not the folder: grep PROHIBITED in the framework’s headers under the SDK path is a thirty-second habit that would have saved a record (GDR-0029 is the correction). The second way:

FoundationModels being in the watchOS SDK means code that imports it compiles. It does not mean the model runs on a watch, or on an older iPhone. Ask at runtime, every time, and design the feature to say so:

switch SystemLanguageModel.default.availability {
case .available: // Say it, an example sentence, a verdict
case .unavailable(let reason): // show the Library and the word; say "waiting for your phone"
}

GDR-0026's rule follows from this: deterministic on the wrist, the model wherever it actually is.

Packages and platform floors

A Swift package declares its platforms once, for the whole package. TimbreKit says macOS 26 and imports AppKit, so no iOS target can link it, and that is correct: the pipeline is the Mac. The Library, the scheduler, the daily pick, the drill checks and the to-do parser are Foundation and Observation, and three apps need them. Hence TimbreCore (ADR-0013): a package declaring macOS, iOS and watchOS, allowed to import nothing platform-specific, with TimbreKit depending on it. The alternative — one package, every shared type wrapped in @available and #if canImport(AppKit) — is noise that spreads.

The same rule, applied to frameworks, gives the rest of the package set (ADR-0015). Code bound to a framework lives in a package that declares exactly the platforms that framework has: TimbreSpeech (AVFAudio and Speech: capture, the transcriber, reading aloud) for the Mac and the iPhone; TimbreModel (FoundationModels: the example writer, the drills’ judges) for the Mac and the iPhone; TimbreReminders (EventKit: the Timbre list) for all three. The Watch cannot link the first two, by construction, which is the point: a floor the compiler enforces beats a comment asking you to remember. The one allowed #if os(macOS) is a few lines of Core Audio device plumbing inside TimbreSpeech, behind the Bluetooth fallback.

App Store, not Developer ID

The Mac ships notarized and direct, with its own updater (ADR-0010). There is no such path on iPhone or Watch: the companion goes through the App Store. That means review, a privacy label — Data Not Collected is a claim you must be able to defend, and Timbre can — and TestFlight for the four devices GDR-0026 names. The sandbox is on, and that is fine. The companion never needed out.

In Timbre

The companion lives in the places the platforms define: an intent for the to-do key, a Control and a widget on the phone, a complication and the Smart Stack on the Watch, a Live Activity for anything in progress. Nothing on the wrist needs the model; the to-do key is Foundation plus EventKit and works in a tunnel. Say it and example sentences happen where the model is and arrive by sync. And the list of what the companion never does — dictation into other apps, command mode on other apps' text, a keyboard extension — is as much a design as what it does.
