# 0004 — A second public seam for the evaluation harness

- **Status:** Accepted
- **Date:** 2026-08-17

## Context

Tuning `TextPolisher`'s instructions is the highest-leverage work on the
roadmap, and it was unmeasurable. With live dictation the input changes on
every take, so there is no way to tell whether a prompt edit improved the
output or the speaker simply enunciated better. The model is also stochastic:
the same transcript polished twice gives different results.

Two further constraints forced the issue:

- The development Mac (a Mac Studio) has **no microphone at all**, so the
  pipeline could not be exercised by speaking into it.
- CI runners have no microphone either, so this was never going to be a
  local-only inconvenience.

[ADR-0002](0002-package-plus-shell-monorepo.md) fixed SpokeKit's public API
at `DictationController` alone. An evaluation tool needs `TextPolisher` and a
file-based audio path, neither of which should become app-facing API.

## Decision

Add a **second, deliberately narrow public seam**, `SpokeEvaluation`, used only
by the `spoke-eval` executable. It exposes three things: polisher availability,
a single-transcript polish, and transcription of an audio file. Nothing in
`apps/Spoke` may import it.

Supporting decisions:

- **Cases assert properties, not exact output.** The model may punctuate and
  phrase freely, so an expected-output string would fail on harmless variation
  and train us to ignore the suite. Cases declare `forbidden` phrases (filler
  that must not survive), `required` phrases (content that must not be lost),
  and whether sentence punctuation is required.
- **Matching is punctuation- and case-insensitive with word boundaries**
  (`TextMatch`), so "um" matches "so um yeah" but not "number".
- **The file path reuses `BufferConverter`** rather than
  `SpeechAnalyzer.start(inputAudioFile:)`. Letting the framework read the file
  would bypass our conversion and end-of-stream drain — precisely the code
  most likely to regress. A harness that skipped them would pass while the
  microphone path clipped every last word.
- **Audio fixtures are generated by `say`**, not recorded, so the corpus is
  reproducible and needs no hardware.

## Consequences

- Prompt changes become measurable, and `--repeat n` makes them *reliably*
  measurable. This is not optional rigour: the first prompt edit appeared to
  fix a case on a single run and scored 0 of 3 when repeated.
- The public surface is wider than ADR-0002 envisaged. Accepted because the
  seam is one type, documented as development-only, and unused by the app.
- Synthetic speech is not real dictation — no accent, no hesitation timing.
  It catches pipeline regressions; it does not replace real recordings when
  judging polish quality.
- `spoke-eval` exits non-zero when a case fails, so it can gate CI once a
  runner has the on-device model available. It cannot today.

## Alternatives considered

- **Put the harness in the test target** (`@testable` needs no new API):
  rejected — `swift test` output is poor for reading nine before/after pairs,
  and model calls are slow and stochastic, which is wrong for a suite expected
  to be fast and deterministic.
- **Make `TextPolisher` public:** rejected — wider than needed, and it invites
  the app to call it directly, bypassing `DictationController`.
- **Assert exact expected output:** rejected, as above.
